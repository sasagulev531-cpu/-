# Актуальная спецификация GUI-казино

В этой версии требования к построению физического игрового мира и управлению им **заменены** запросом пользователя на полностью инвентарное GUI-казино. Старые артефакты управления блоками и соответствующие команды не используются. Исторические требования к ним более не применяются.

## Сохранённые инварианты

- Paper API 1.21.x, JDK 21, без NMS.
- Европейская рулетка с числами 0–36, одним зеро, 18 красными и `EUROPEAN_ORDER`.
- Все ставки и коэффициенты: `STRAIGHT` 35, `SPLIT` 17, `STREET` 11, `CORNER` 8, `SIXLINE` 5, `DOZEN`/`COLUMN` 2, `RED`/`BLACK`/`EVEN`/`ODD`/`LOW`/`HIGH` 1; `return-stake-on-win` управляет дополнительным возвратом ставки.
- Ставки игрока на позицию объединяются; два игрока на одной позиции независимы (`UUID:positionKey`). Лимит позиции — общий (`>= max-bet`), лимит суммы раунда — персональный.
- Монеты только через FCP `EconomyService`, без Vault и отдельной боевой экономики; `FileBalanceProvider` — только fallback. При `fcp-currency: dcoins` используются DCoins. Никаких изменений кода или конфигов сторонних FCP-плагинов.
- Старые ключи `config.yml` сохранены, даже если уже не управляют отображением. Права администратора обязательны для `give`, `set`, `reload`.

## Актуальный игровой поток

`/roulette` открывает 54-слотовое меню; через него выбираются номинал, число, внешняя ставка либо комбинация. Один общий таймер на сервер ведёт фазы `BETTING → SPINNING → RESULT`, результат один на всех. Ставка дебетуется при принятии; игрок может вернуть все свои ставки во время приёма. Выигрыш начисляется по UUID и не зависит от открытого меню. Штатное выключение до расчёта возвращает ещё открытые ставки. Подробнее — в `README.md` и `HOW_IT_WORKS.md`.

## Проверка

Юнит-тесты проверяют раскладку GUI, наборы выигрышных чисел, коэффициенты, лимиты и разделение ставок. Интеграционная приёмка с реальным Paper + FCP необходима отдельно; изменения в production без согласования не устанавливать.
